# Mingli / Zhenyi Bazi 可复现评测协议

## 目的

验证 Muse 与真一体系的集成质量，不把项目 README 自报的模型分数当作已复现结论。

## 已知上游工作流

真一公开说明采用“先排盘、再推演”。模型维护者在评测 Issue 中指出，直接把出生参数交给模型并要求单轮选择题作答，并不等同于其官方评测流程。其建议是先提供程序核验后的命盘，再问目标问题；随后在同一会话中给出选项进行追问。详见：
- https://github.com/ZHENYI-ORG/Mingli-AI
- https://github.com/ZHENYI-ORG/Mingli-AI/issues/1
- https://github.com/ZHENYI-ORG/Zhenyi-bazi

因此任何分数必须记录排盘器版本、模型权重版本、system prompt、温度、token 上限、轮数、问题顺序、数据集版本和评分规则。

## 测试集分层

1. **历法边界集**：立春前后、十二节令交界、0 点换日、23 点夜子时、早子时、时辰交界。
2. **时区集**：IANA 时区、夏令时切换前后、不同 UTC offset；无时区信息时必须拒绝猜测。
3. **真太阳时集**：不同经度、均时差修正开关、校正跨日/跨时辰。
4. **农历集**：闰月、闰月取法、农历转公历边界。
5. **未知输入集**：缺出生时刻、仅知时辰、未知经度；必须保留不确定性，不填造数据。
6. **推演质量集**：命题、支持规则、反例、替代流派、不可判定题；评分由可审查答案键或专家复核完成。

## 每条案例的最小记录

- case_id、来源与授权状态、脱敏输入
- 输入日历体系、时区、经度（如有）、性别是否为显式输入
- Muse CalendarContext 版本和 fingerprint
- Zhenyi-Bazi commit/version、原始响应 hash、解析后四柱
- 四柱差异字段与差异原因（禁止只记“通过/失败”）
- Mingli model ID、权重 hash、prompt hash、生成参数
- 第 1 轮命盘+问题请求、第 2 轮选项追问请求及完整响应
- 评分、审查者、反例和不确定性

## 通过门槛

- 所有边界案例必须可重放；输入缺失时不得静默补默认值。
- 同一配置重复运行结果必须确定；若模型采样导致文字差异，计算结果仍须一致。
- 四柱对照不一致时 fail-closed，保留双方输出和口径解释，不自动挑选某一方。
- 不以模型自报的“置信度”作为概率。
- 任何传统命理断语只进入 idea/hypothesis；不得自动升级为事实 claim。
- 在至少 30 个有授权、可审查案例上完成独立复核前，不发布“准确率”宣传指标。
