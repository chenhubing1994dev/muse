# Muse 宇宙级产品体验愿景与逐项交付路线图

日期：2026-11-13
状态：长期产品方向；按阶段逐项实现，不代表下列能力已经全部完成。

## 一、产品愿景

将 Muse 建设为一个本地优先、可持续运行、可组合专业能力、可追踪经验并能把灵感转化为真实成果的「宇宙意识中枢」与个人超级应用。

「宇宙最强 APP / 宇宙最强意识体」是产品追求与视觉表达，不是对软件具有主观意识、无限智能或超自然能力的事实声明。产品价值必须由真实能力、可靠交付、可验证结果和用户体验证明。

## 二、用户明确要求的交付方式

1. **逐项介绍**：每个功能先解释它是什么、解决什么问题、目前真实做到哪一步。
2. **逐项实现**：按依赖和价值排序，一次聚焦一个完整功能，避免同时堆砌大量只有外观的空壳模块。
3. **逐项验证**：每个功能都要有真实数据路径、后端/API、持久化（适用时）、错误处理、自动化测试和可复现验收。
4. **图文说明**：每个功能配架构图、流程图、状态图或真实界面截图。所有视觉材料必须明确标注「真实运行截图」或「概念示意图」；概念图不得冒充实机截图。
5. **教会用户使用**：提供中文操作步骤、入口位置、所需权限/依赖、预期结果、常见故障与恢复方法；尽可能把引导直接做进桌面端。
6. **如实汇报**：区分已实现、部分实现、仅后端可用、计划中、被阻塞。没有实机证据就不能声称实机通过；没有真实生成的作品就不能声称视频链路完工。
7. **持续维护本地记忆**：每轮更新本路线图、docs/PROGRESS.md、阶段报告与用户指南，使新会话可从本地文件恢复目标、决策、现状和下一步。

## 三、产品体验原则

- 一处总览：以 Muse Commander 为唯一调度与授权中心，统一展示系统健康、任务、Agent、研究、知识、灵感、创作和进化状态。
- 一套账本：灵感、来源、研究、Claim、反面证据、实验、决策、失败、创作项目、MP4/ZIP 成品、用户反馈和改进提案可追溯关联。
- 一条闭环：捕获灵感 → 研究与反证 → 知识沉淀 → 专家编排 → 原型/作品 → 测试与审查 → 用户反馈 → 改进提案 → 授权升级 → 回写经验。
- 真正可操作：界面按钮必须连接真实 API 与状态转换；只读状态必须明确标识，不能把数字装饰成可执行功能。
- 可信的自主性：可自主研究、提出假设、整理经验和准备提案；涉及安装、外发、付款、删除、服务部署、代码升级等高风险行为仍须遵循授权策略。
- 本地优先与成本透明：私人记忆默认本地；未知/付费额度 fail-closed；资源并发根据实测容量和硬上限。
- 可恢复：任务有状态、审计、取消/超时/重试预算、故障恢复和回滚策略。
- 可访问：中文优先、键盘可用、响应式布局、清晰层级、低干扰动效与可读状态反馈。

## 四、功能版图与分阶段实现顺序

下列是目标版图。每项必须在实现前重新核对现有模块，优先复用现有后端能力和开源适配器，不重复建设第二套队列或调度器。

### 第一阶段：桌面操作闭环
1. **宇宙总览 / 意识中枢**：真实连接状态、系统健康、活跃任务、灵感与成品数量、待处理事项；每个数字可追溯到 API 数据来源。
2. **使用指南与新手引导**：分步骤介绍功能，能跳转到实际界面，展示权限、依赖、预期结果和边界。
3. **任务中心 / Commander**：查看任务详情与状态；经后端授权执行批准、取消等合法转换；记录操作者、理由与审计事件；危险动作二次确认。重试/恢复须先证明幂等和安全边界。
4. **Agent 舰队**：在线/忙碌/离线、能力、分配任务、真实性能数据、健康与故障；没有 Agent 就显示未配置或离线，不伪造。
5. **灵感工作台**：输入、分类、来源和隐私边界；一键建立研究任务或创作候选；历史记录可检索。

### 第二阶段：研究与知识文明
6. **Research Wiki**：节点与关系浏览，支持来源、Claim、实验、结论、反证、替代解释和失败记录；标记事实/解释/经验/假设/象征灵感/虚构设定。
7. **深度研究中心**：检索、阅读、交叉核验、反面证据、来源质量、授权与版本；结论保留置信度与未解决问题。
8. **长期记忆中心**：User Track 与 Agent Track 分离；来源、时间、置信度、版本、修订和遗忘/纠错流程；推测不得自动写成用户事实。
9. **玄学灵感实验室**：易经、紫微、奇门、大六壬只用于文化推演与假设生成；明确标注不可验证性，不替代事实证据或工程验收。

### 第三阶段：创造与成果宇宙
10. **创作工坊**：把文字灵感转为软件、视频、图像、游戏、自动化流程及其他作品候选。
11. **视频创作中心**：真实连接 ComfyUI/Wan、FFmpeg；任务状态、素材、工程、MP4、ZIP、Manifest、技术指标和播放/下载验收一体化。
12. **成果图书馆**：按项目、版本、类型和状态检索；预览、下载、复核、反馈；保存真实文件哈希与产物关系。
13. **创作反馈与作品评审**：accept/revise/reject 等反馈进入同一账本，保留人工决策与来源；反馈不是自动批准代码升级。

### 第四阶段：自主进化与运行治理
14. **进化实验室**：能力雷达、研究提案、改进 Ticket、独立审查、测试、授权整合、回滚和经验回写。
15. **运行中心**：Worker、Watchdog、周期任务、提醒、暂停/恢复、崩溃恢复、资源快照和日志。
16. **工具与 Provider 中心**：能力发现、健康检查、权限、免费额度/成本、适配器状态；未知工具不自动执行。
17. **设置与部署**：本地数据目录、备份恢复、网络配对、安全设置、更新、托盘、安装/卸载与开机运行授权。

## 五、每项功能的完成定义（Definition of Done）

- 用户目标和当前能力边界写清楚。
- UI 入口与交互可用，文案不夸大。
- API/服务端实现真实状态读取或受控状态变更。
- 数据模型与持久化策略明确；敏感字段最小化。
- 有加载、空状态、失败、超时和恢复反馈。
- 对关键业务规则先写失败测试，再实现（TDD）。
- 单元/集成/前端/构建测试按改动范围执行并记录结果。
- 真实桌面运行时进行截图与鼠标/键盘验收；若环境不允许，明确列为未验证。
- 有图解、中文用户操作说明、预期结果和排障方法。
- 更新 `docs/PROGRESS.md`、独立阶段报告和本用户指南。
- 只有满足验收条件才标记完成；不能用 Mock、静态数字或概念图代替真实能力。

## 六、视觉与教学规范

- 采用深空星图、东方玄枢意象与精致未来科技语言，形成统一设计系统；美术不能牺牲可读性、性能和可操作性。
- 每个复杂模块至少提供一张结构/流程图；关键操作提供步骤图或真实截图。
- 真实截图注明构建版本、运行环境和拍摄时间；示意图加注「概念示意，不代表当前已实现」。
- 指引按「入口 → 操作 → 预期结果 → 失败处理」组织，用户不需要猜测下一步。
- 重要状态同时使用文字与图标/颜色表达，避免仅靠颜色；破坏性操作提供明确确认与撤销/恢复说明。
