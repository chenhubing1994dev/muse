# B356｜视频工厂质量优先生成基线与发布门禁

日期：2026-11-25

## 本轮目标

将 Muse 视频工厂从低分辨率预览生成推进到模型能力范围内的最高质量母版，并把视觉诊断、人工审片和发布分辨率门禁接入同一产品链路。MP4 生成成功不等于视觉合格，更不等于可以发布。

## 已落地

### 1. Wan 2.1 1.3B 质量优先基线

- 新增显式配置 wan21_t2v_1.3b_480p_quality_first。
- 默认分辨率：横屏 832×480、竖屏 480×832、方形 480×480。
- 默认 16 FPS、5 秒、81 帧（满足 Wan 的 4n+1 帧约束）、20 sampling steps；CFG 6、shift 8。
- 单镜头最长 5 秒；多镜头时长分配按 16 FPS 和 4n+1 规则计算。
- 生成任务、视频提示工作室、商机创作和自主研究的视频任务统一使用质量优先默认值。
- GPU 提交前同时检查 70% 空闲显存比例和至少 7.7 GiB 空闲显存；不满足时阻止提交，不用估算值冒充真实显存。

官方模型说明：Wan 2.1 T2V 1.3B 面向 480P，不应把它当作原生 720P/1080P 模型。参考：https://github.com/Wan-Video/Wan2.1

### 2. 视觉诊断进入产品本体

- AI 生成产品的 Manifest 和 product.zip 自动包含 visual-quality-report.json。
- 报告 SHA-256 与 Manifest 绑定；产品验证会检查报告结构、哈希、信号数和 ZIP 成员。
- 字幕批准后的重新封装会重新分析输出视频并生成新报告，避免沿用旧版本审片证据。
- 视觉诊断缺依赖或无法解码时标记 unavailable，不会伪造质量分数。

### 3. 发布质量门禁

- 发布质量报告增加 delivery_resolution 检查：视频短边至少 720 像素。
- 低于 720P 时标记 blocked；只改宽高元数据不能通过。
- 480P Wan 母版必须经过真实 AI 超分到至少 720P，再进入发布审查。
- 自动视觉诊断仍不代表人物一致性、动作自然度或电影审美合格；人工逐镜审片仍是必需步骤。

### 4. 提示词与审片界面

- video_prompt_composer 升级为 spec v2；默认电影模式增加主体/动作单一性、构图层次、镜头运动、焦段景深、光影连续、材质可信和角色外观连续约束。
- 默认负面提示覆盖人物变脸、服装漂移、肢体/手指异常、闪烁、重影、文字乱码和水印等常见缺陷。
- VideoVisualReview 显示自动诊断状态、抽样帧时间、亮度/光流变化、异常信号及帧级清晰度/对比度/阴影/高光数据，并明确说明这些指标不具备语义理解能力。

## 验证结果

- Python 定向回归：286/286 passed，0 failed，覆盖视觉报告、防篡改、发布门禁、Wan 工作流、视频产品、任务 Worker、提示词工作室、商机和自主研究任务。
- UI Node tests：66/66 passed。
- Svelte diagnostics：0 errors、0 warnings。
- Vite production build：成功；使用 Vite native config loader。
- 真实样片本地抽样：24 帧；检测到 6 个低对比度信号和 2 个较大亮度变化信号，均只作为人工检查提示。

## 尚未完成的真实画质阻塞

- 当前 Runner 无法连接本机 ComfyUI 127.0.0.1:8188，所以本轮没有实际启动 GPU 生成，也没有验证 480P 新参数在 RX 6750 GRE 上的真实耗时、显存峰值或画面效果。
- 目前没有可验证的 AI 视频超分模型/工作流；因此 480P 母版会被 720P 发布门禁阻止，不能声称已经达到可发布水准。
- 当前 OpenCV 报告是低层图像和光流启发式，不会识别人脸、角色身份、人体动作、手部结构或电影美学。
- 还需要在 ComfyUI 可用后，验证 480P 实际样片、接入真实 AI 超分，并引入经过许可的语义视觉审片能力；之后再用人工标注样片集校准人物一致性、动作自然度和镜头质量标准。

## 结论

本轮完成的是质量优先的生成基线、可追溯诊断、界面展示和硬性发布门禁；不是“已经产出电影级成片”。当前 480P 母版与语义视觉审片/AI 超分仍是发布前的明确阻塞项。
