# Muse 总体开发路线图

更新：2026-11-09

本文件把此前已确认的 Muse 目标、现有 Backlog 与阶段进度合并成一条依赖有序的主路线。它是规划索引，不代表其中所有项目已经实现或正在后台运行。具体状态以 `docs/PROGRESS.md` 与 `docs/CAPABILITY_BACKLOG.md` 的最新验收记录为准。

## 北极星目标与架构边界

Muse 是本机自主研究、知识积累、灵感创造与安全进化系统：ChatGPT 负责指挥和目标控制，Muse 本地程序负责受限执行、持久化与主动工作。Muse Commander 是唯一调度中心；不新增平行 Scheduler/Queue。

- 主动发现问题：从创造者书签、长期兴趣、历史研究、失败经验、能力缺口和未审主张中发现新课题。
- 深度研究：搜索、阅读、来源追溯、交叉比较、反证搜索、替代解释和可复现条件。
- 创造性灵感：易经、紫微、奇门、大六壬及其他象征体系、创造者经验和跨领域知识可启发问题与假设；这些内容绝不是事实证据、预测或结论。
- 知识复利：来源、假设、实验、主张、决策、失败与经验形成可追溯图谱；保留失败和被否决方案。
- 自主进化：把发现转成能力、技能、提案、原型和可体验成果；任何代码变更仍须经过人工批准、隔离测试、独立审查与可回滚流程。
- 主动汇报：重要发现、可执行创意、风险和进度进入本地提醒/成果队列；明确区分本地生成报告与已成功推送到聊天/手机的通知。

硬性边界：不把私密反馈/记忆拼入公共搜索；不执行任意模型生成命令；不自动批准、发布或外发；未知来源许可/安全状态保持待审；免费额度优先，未知额度不付费 fallback；服务安装、开机自启、驱动和高影响系统修改须单独批准。项目是 non-Git 工作区，写入前必须读当前文件与 revision，逐步验证并记录哈希/结果。

## 依赖有序的开发阶段

### P0 — 研究实验执行与反馈闭环（当前最高优先级）

- B-060：反馈驱动研究选题、隐私隔离、支持/反证双向研究计划。
- B-061：反馈提案 `proposed → researching → ready_for_review`，来源按 URL 幂等归档，证据不足时续跑。
- B-062：第一阶段已完成——反馈研究计划接入既有 ExperimentBridge/TestRunner；固定白名单、只读快照、持久化结果/失败、提案/反馈/计划关联和幂等重试。
- B-063：可选独立 Reviewer 通道已接线；必须配置不同本地模型并确认 endpoint 当前暴露该模型。当前只有一个 Builder 模型，生产审查保持 pending；same endpoint 的不同模型不宣称 provider-level independence。
- B-064：Claim dossier 与自主研究报告已接入证据覆盖/来源质量画像（支持与反证覆盖、审查 verdict/质量/独立性、来源完整性与已审谱系）；不自动打分、不自动升级 Claim。
- B-065：事实级引用索引将综合陈述映射回 source ID、URL、citation_id 与 SHA-256 快照；仅供追溯，仍需人工核对原文。
- 后续验收：真实第二模型审查运行、来源可读率/原始文件核验、事实与引用矛盾检查、实验可复现/取消/资源边界；任何主张升级必须有独立审查，工程回归测试不得冒充事实证据。

### P1 — 自主研究与深度学习

- 完成 B-007 / B-015 / B-029 / B-039 余项：来源可读率、来源身份/可信度评估、日期与原始文件核验、跨来源事实核验、事实级引用报告、定时研究与 Planner 安全调用。
- 课题池动态化：知识缺口、重复失败、待审 Claim、未研究象征假设、创造者书签和新网站/作者/项目共同驱动选题；新课题不得抢占尚未完成的高优先级研究。
- 研究输出不只复述资料：提出跨领域组合、明确变量、Test/Falsifier、替代解释、创造候选和可交付成果。
- 对争议叙事保留原始说法、出处、支持与反面证据、证据质量、来源关系和不确定性；不因神秘、流行、前沿或争议而提高可信度。

### P2 — Research Wiki、长期记忆与哲学经验库

- 延续 B-017 / B-018 / B-028：ResearchKnowledgeStore 作为来源、Idea、Experiment、Claim、Decision、Failure 的关联图谱；支持/反驳/相关/矛盾/替代/测试/解决缺口关系。
- Obsidian Vault (D:\AI AGENT\Muse\vault) 保持 SQLite 权威源与安全 Markdown 镜像。B-066 已完成显式节点选择的单向 create-only export；B-067 已完成只读哈希/来源更新时间审计；B-068 已完成来源正文哈希/citation ID 校验与双来源差异候选持久化；B-069 已完成反证候选、替代解释 Idea、alternative 边与失败经验展示。
- 下一步 B-070：改进提案→人工批准→测试→Reviewer→回滚闭环，并为每个候选提供逐条审查记录。逐笔 diff、人工编辑批准回流、冲突解决和双向同步仍未实现。
- 把成功、失败、偏差、用户反馈、旧哲学原则修订与新灵感写入长期经验；允许原则被细化、降级或替换，但保留来源、版本和审查轨迹。
- 语义检索、低频 consolidation/Reflection、记忆过期与冲突治理按隐私与可审计性推进。

### P3 — 自我进化与可验证创造

- 延续 B-004 / B-005 / B-033 至 B-037：能力雷达、改进提案、独立审稿、基线/候选测试、Ticket 审批、执行 Journal、崩溃恢复、hash-guarded rollback。
- 先完善真实独立 Reviewer（不同身份；不同模型/provider 的独立性要如实说明），再接通已批准提案到代码变更 Ticket 的完整路径。
- 研究/灵感候选可自动形成静态原型、工作流或设计方案；可执行代码变更必须保留人工批准与既有安全执行器，不允许模型自行给自己授权。
- 记录实验失败、反证和未通过审查的原因，避免重复尝试；失败不自动等同外部假设被反驳。

### P4 — 自主运行、恢复与主动汇报

- 延续 B-001 / B-002 / B-010 至 B-012 / B-016 / B-019 / B-029：任务租约、心跳、进度事件、停滞检测、Routine Scheduler、本机提醒、成果报告和自主研究周期。
- 补齐暂停/恢复、崩溃续跑、取消、退避、资源降载、执行状态回报和报告去重。
- 将高价值想法、研究成果、待审事项和风险进入提醒队列；本地定时报告不能宣称为已推送聊天或手机。
- Windows 常驻服务、登出后运行、开机自启和服务自动重启需先补足停止/资源/隐私/恢复测试，并按项目已有权限规则单独批准。

### P5 — Commander、Agent 生态与并发调度

- 延续 B-018 / B-024 / B-025 / B-027：唯一 Commander、Ruflo DAG/Swarm、任务生命周期、资源感知并发、能力路由、角色协作和可审计消息交接。
- Agent 管理补齐：配置服务发现（只探测明确配置的 endpoint，不扫描/运行未知程序）、heartbeat online/busy/offline、真实任务表现评分、能力与成本/延迟画像、失败隔离、超时/取消/恢复。
- Reviewer 角色必须与 Builder 身份分离；跨 Agent 输出均视为不可信数据，不获得额外工具权限。
- 32 路逻辑编排与 DAG/Worker 压力测试已有历史验收；生产 worker 数仍由 ResourceGovernor 决定，32 路模型推理/ACP CodingAgent 不得据此宣称已验证。继续验证 OpenCode ACP Provider 时，只使用受控 Runner 配置边界。

### P6 — 桌面 Agent 调度中心

- 延续 B-022 / B-023 与 `docs/UI_PRODUCT_SPEC.md`：Rust/Tauri 桌面端、前端 UI、Python 本地后端；统一展示 Agent、DAG、任务、审查、知识、工具状态和真实事件时间线。
- 保留 Cyber-Mythic Pixel / 中国古典神话意象的视觉方向；优先可读性、真实状态、键盘可访问性和减少动态效果。
- 前端只通过 loopback 安全 API 访问数据，不直接操作 SQLite/shell；默认不开放公网或 LAN 控制。

### P7 — 运行环境与可选模型能力

- WebCodex Runner 稳定性：断线检测、session/job 状态观察、恢复原项目/会话、任务续接、执行结果核验；不能恢复时如实报告。
- 本地 llama.cpp / LM Studio 模型只作为可选快速分类、灵感综合或备用 Reviewer；核心研究/调度不依赖本地 LLM，也不依赖新增云端 AI API。Provider 必须 loopback/allowlist/免费额度与凭证边界明确。
- 外部工具/Provider 仅通过已登记 Capability/Adapter 接入；未知能力不执行。

### P8 — 视频工厂（长期暂缓，不抢占研究主线）

- B-031：Muse Commander + ComfyUI + Velorn + FFmpeg/FFprobe，目标是一键产出可验证影片。
- 先解决 RX 6750 GRE 的真实 GPU 推理兼容性，再评估模型、节点、故事生成、角色一致性、字幕配音、时间线和成片审查；GPU smoke 未通过前不扩大模型下载或安装 custom nodes。
- 此线保留在长期路线，不得挤占 P0–P5 的自主研究、知识与进化闭环。
