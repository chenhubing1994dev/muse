# B355｜视频视觉质量诊断证据包（第一阶段）

日期：2026-11-25

## 目标

把视频工厂从只证明 MP4 技术完整、提供联系表，推进到逐帧可追溯的视觉诊断；不以文件可生成或技术 QA 通过作为视觉合格结论。

## 本阶段实现

- 新增 `src/muse/video_visual_quality.py`：使用已存在的可选 OpenCV/NumPy 环境，对视频均匀抽样，记录亮度分位数、对比度、拉普拉斯清晰度启发式、饱和度、阴影/高光占比。
- 对相邻抽样帧记录亮度变化、光流中位数、P90 光流及全局运动扣除后的残差；异常只作为待检查信号，不把场景切换误判为闪烁，也不把光流当成人体动作理解。
- 通用视觉审片证据包和标准多平台发布包均增加哈希绑定的 `visual-quality-report.json`；报告与原 MP4、产品 Manifest、技术 QA、联系表和发布质量报告一起校验。旧版仅含联系表的证据包仍可读取。
- Status API 的视觉审片历史响应返回诊断报告及其哈希，前端 API 类型同步扩展；旧数据没有视觉诊断时保持可选字段兼容。
- 分析器缺少依赖或无法解码时明确记录 unavailable，不伪造分数；该报告永远不自动批准审片或发布。

## 明确边界

- 当前是低层图像/运动诊断，不具备人脸/角色识别、跨镜人物身份匹配、动作语义、自然度或电影摄影审美理解。
- 指标阈值只产生人工检查提示；暗调镜头、高光、柔焦、快速剪辑都可能是有意设计。
- 人物一致性、肢体结构、动作自然、镜头表达、材质可信仍需后续接入经许可的视觉模型/人工逐镜审片，并用真实样片标注集校准。
- 不启动 GPU、ComfyUI/Wan、下载模型或调用付费 API；不更改原视频、模型或用户作品。

## 验证

- Python 3.11 / psmux 定向回归第一轮：75/75 通过，覆盖视觉诊断、证据包、防篡改、场景分析与视频产品构建。
- 真实样片 `ember-fire/火种不灭.mp4`：本地 OpenCV 成功抽样 24 帧，报告 6 个低对比度帧信号和 2 个较大亮度变化信号；这些信号均要求人工查看，不构成自动失败结论。
- 第二轮扩展后 Python 定向回归 286/286 passed，0 failed；UI Node tests 66/66 passed；Svelte diagnostics 0 errors/0 warnings；Vite production build 成功。后续 480P 质量优先生成基线、显存门禁和发布分辨率门禁见 docs/PROGRESS_B356_VIDEO_QUALITY_FIRST_480P.md。
